# Veridraw: Микросервисная система розыгрышей

Демонстрационный проект, демонстрирующий корректное применение современных технологий для построения надежных распределенных систем. Обеспечивает полное управление жизненным циклом розыгрышей, покупку билетов и гарантированную доставку уведомлений победителям.

---

## 🚀 Быстрый старт

### Предварительные требования
Для работы необходим установленный и **запущенный** Docker Engine:
- **Windows**: Запустите Docker Desktop и дождитесь его готовности.
- **Linux/macOS**: Служба Docker должна быть активна. Проверить статус: `docker info`.

> ⚠️ **Важно:** Все команды управления необходимо выполнять, находясь в **корневой директории проекта** (там, где лежит `docker-compose.yml`).

### Пошаговый запуск
1. Клонируйте репозиторий: `git clone https://github.com/veezday/veridraw.git`
2. Запустите все сервисы:
    - **Windows**: `.\manage.ps1 up`
    - **Linux/macOS**: `./manage.sh up`
3. Дождитесь завершения запуска (сервисам требуется некоторое время для инициализации).
4. **Вариант А (Нагрузочное тестирование)**: Выполните `./manage.sh load-test`. Наблюдайте за процессом в Grafana: `http://localhost:3000` → **Dashboards** → **Veridraw** → **Observability**.
5. **Вариант Б (Ручное тестирование)**:
    - Получите токен доступа: `./manage.sh token`
    - Откройте Swagger: `http://localhost:8082/swagger-ui.html` или `http://localhost:8083/swagger-ui.html`
    - Нажмите **Authorize**, вставьте полученный токен в поле value и подтвердите.

## 🛠 Технологический стек

| Категория            | Технологии и компоненты                                                                                                                                                     |
|:---------------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Backend**          | Java, Spring Boot (предп.), OpenTelemetry Java Agent                                                                                                                        |
| **Микросервисы**     | `gateway` (роутинг, лимитеры), `draw-core` (бизнес-логика), `notify-worker` (обработка событий)                                                                             |
| **Хранение данных**  | PostgreSQL (основные данные, Outbox/Inbox), Redis (rate limiting)                                                                                                           |
| **Брокер сообщений** | Apache Kafka (топик `draw-events`, полиморфная JSON-сериализация)                                                                                                           |
| **Безопасность**     | Keycloak (аутентификация, управление публичными ключами)                                                                                                                    |
| **Observability**    | OpenTelemetry Collector (единая точка сбора), Prometheus (метрики), Jaeger (трейсы), Loki + Promtail (логи), cAdvisor (метрики контейнеров), Grafana (дашборды)             |
| **Инфраструктура**   | Docker, MailHog (тестовый SMTP-сервер), Random.org API (генерация победителей), k6 (нагрузочное тестирование)                                                               |

## 🏛 Архитектурные принципы

Архитектура спроектирована с упором на следующие ключевые аспекты:

- **🛡 Отказоустойчивость и согласованность данных**
    - Паттерны **Outbox** (`draw-core`) и **Inbox** (`notify-worker`) с использованием PostgreSQL для гарантированной и идемпотентной доставки событий через Kafka (топик `draw-events`).
    - Механизмы повторных попыток: фоновый опрос каждые 5 секунд, API для ручного управления (`resend`), резильентная отправка email (до 3 попыток в MailHog) и fallback-маршруты в шлюзе при недоступности целевых сервисов.
- **🔐 Безопасность и контроль доступа**
    - Централизованная аутентификация и валидация JWT через **Keycloak** (сервисы загружают публичные ключи при старте).
    - Многоуровневый **rate-limiting** на уровне API Gateway (по IP и по пользователю) с использованием **Redis**.
    - Обогащение запросов контекстными заголовками (`X-User-Id`, `X-User-Name`, `X-User-Email`) перед внутренней маршрутизацией.
- **👁 Полная наблюдаемость (Observability)**
    - **Метрики:** JVM, кастомные метрики сервисов, метрики инфраструктуры (PostgreSQL, Redis, Kafka, Keycloak) и контейнеров (cAdvisor) собираются через `otel-collector` в **Prometheus**.
    - **Логи:** Агрегация логов Docker-контейнеров по стеку **Promtail** → **Loki**.
    - **Трейсинг:** Сквозной трейсинг (OpenTelemetry) для `gateway`, `draw-core` и `notify-worker` с экспортом через `otel-collector` в **Jaeger**.
- **🧩 Четкое разделение ответственности**
    - **API Gateway (8081):** Единая точка входа, маршрутизация, защита, обогащение заголовков и обработка fallback-сценариев.
    - **Draw-core (8082):** Управление жизненным циклом розыгрышей (`CREATED`, `ACTIVATED`, `COMPLETED`, `CANCELLED`) и билетов. Интеграция с **Random.org API** для честного выбора победителя. Транзакционное сохранение Outbox-событий с полиморфной JSON-сериализацией (с дискриминатором `type`) для Kafka.
    - **Notify-worker (8083):** Асинхронная обработка событий из Kafka, управление inbox-очередью и отправка уведомлений с возможностью ручного контроля через специализированные API-эндпоинты.

## 📘 Руководство по использованию

### 📚 Swagger — тестирование API
1. Откройте Swagger нужного сервиса (ссылки выше).
2. Для защищённых эндпоинтов:
    - Выполните в терминале: `./manage.sh token`
    - Скопируйте выведенный токен.
    - Нажмите **Authorize** в Swagger, вставьте токен в поле `value` и нажмите **Authorize** снова.

### 📈 Grafana — дашборды
1. Откройте `http://localhost:3000` (логин: `admin`, пароль: `admin`).
2. Перейдите в **Dashboards** → **Veridraw**.
3. Доступные дашборды:
    - **Observability**: основные метрики, latency, throughput, error rate.
    - **Custom Metrics**: кастомные бизнес-метрики сервисов.
    - **Trace**: визуализация трейсов и связанных логов.

### 📬 MailHog — проверка писем
1. Откройте `http://localhost:8025`.
2. Все письма, которые `notify-worker` отправляет через `emailService`, попадают сюда.
3. Можно открыть письмо и увидеть raw-сообщение, заголовки и тело.
> 💡 **Совет:** Если письмо не появилось, проверьте, что `InboxEvent` успешно обработан (статус `published=true` в БД `notify-worker`).

### 🔐 Keycloak — управление доступом
1. Откройте `http://localhost:8080` и войдите в Admin Console (`admin`/`admin`).
2. Ключевые разделы:
    - **Clients**: настройка клиентов `gateway`, `draw-core`, `notify-worker`.
    - **Users**: создание и управление тестовыми пользователями.
    - **Realm Settings → Keys**: публичные ключи, которые микросервисы загружают при старте для валидации JWT.

### 🔍 Jaeger — просмотр трейсов
1. Откройте `http://localhost:16686`.
2. В выпадающем списке **Service** выберите нужный сервис (`gateway`, `draw-core` или `notify-worker`).
3. Нажмите **Find Traces**.
4. Кликните по трейсу, чтобы увидеть каскад спанов и время выполнения каждого шага.
> 💡 **Совет:** При ошибке в API Gateway в HTTP-ответе возвращается заголовок или поле с `traceId`. Вставьте его в поле **Trace ID** в Jaeger для мгновенного точного поиска.

## ⚙️ Управление проектом

Скрипты `manage.ps1` (Windows) и `manage.sh` (Linux/macOS) унифицируют управление.

### Windows (PowerShell)
```powershell
# Если появляется ошибка "выполнение скриптов отключено", выполните один раз:
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser

# Запуск для всех или конкретных сервисов:
.\manage.ps1 <команда> [сервис1 сервис2 ...]
```

### Linux / macOS (Bash)
```bash
# Дать права на выполнение (один раз)
chmod +x manage.sh

# Запуск для всех или конкретных сервисов:
./manage.sh <команда> [сервис1 сервис2 ...]
```

> 💡 **Правило:** Если не указывать имена сервисов, команда применится ко **всем** сервисам проекта сразу. Пример: `./manage.sh rebuild api db` или `.\manage.ps1 load-test`.

### Справочник команд
| Команда         | Описание                                                                              |
|:----------------|:--------------------------------------------------------------------------------------|
| `up`            | Запустить сервисы                                                                     |
| `down`          | Остановить и удалить контейнеры                                                       |
| `rebuild`       | Пересобрать (с кэшем) и перезапустить сервисы                                         |
| `rebuild-clean` | Полная пересборка без кэша и перезапуск                                               |
| `clean`         | Полная очистка (контейнеры, volumes, образы). *Без аргументов запросит подтверждение* |
| `token`         | Получить и вывести access token из Keycloak для авторизации в API                     |
| `load-test`     | Запустить нагрузочные тесты k6 (аргумент: имя скрипта, например `01.js`)              |
| `status`        | Показать текущий статус контейнеров                                                   |
| `log`           | Просмотр логов в реальном времени                                                     |
| `help`          | Показать справку по командам                                                          |
